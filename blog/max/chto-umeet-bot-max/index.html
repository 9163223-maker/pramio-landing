Что умеет бот MAX

Бот MAX — это не только автоответчик. Через Bot API можно строить последовательные сценарии, принимать данные пользователя, реагировать на события и подключать внешнюю бизнес-логику.

Диалог и действия пользователя

Бот может отправлять сообщения и выводить кнопки, которые запускают разные действия. В текущем API предусмотрены, в частности, переход по ссылке, запрос контакта, запрос геолокации, открытие Mini App и отправка заранее заданного сообщения боту.

Это позволяет строить не только FAQ, но и сценарии заявки, записи, подбора, обратной связи или квалификации обращения.

Диплинки и источники перехода

Бота можно открывать специальной ссылкой вида https://max.ru/<botName>?start=<payload>. Параметр запуска передаётся боту и может использоваться как контекст: например, чтобы понять, с какой страницы, публикации или рекламной кампании пришёл пользователь.

Для бот-дилпинка MAX сейчас ограничивает payload 128 символами. Поэтому в ссылку разумно передавать короткий идентификатор, а подробные данные хранить на своей стороне.

События и автоматизация

Через Webhook сервер может получать выбранные типы событий и запускать бизнес-логику: обновлять состояние диалога, записывать данные, уведомлять сотрудника или обращаться к разрешённой внешней системе.

Webhook должен использовать HTTPS. Для дополнительной проверки MAX позволяет задать секрет, который приходит в заголовке webhook-запросов.

Mini App внутри MAX

Если обычного диалога недостаточно, к чат-боту можно подключить мини-приложение. Оно подходит для интерфейсов с каталогом, формой, календарём, калькулятором или большим количеством вариантов. При этом Mini App не является автономным сервисом MAX: он привязан к боту.

Что важно не обещать

  • Не каждое действие интерфейса MAX доступно через API
  • Возможности зависят от прав бота и типа объекта
  • Часть функций требует верифицированного профиля и модерации
  • API развивается: методы и ограничения нужно проверять перед оценкой проекта
  • Интеграция с внешней системой возможна только при наличии доступного API и необходимых прав

Поэтому корректная разработка начинается с проверки конкретного сценария, а не с обещания «бота любой сложности».
