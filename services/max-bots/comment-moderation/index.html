Бот для модерации комментариев в MAX

Настраиваем обработку новых комментариев через MAX API: бот получает событие, проверяет заданные правила и выполняет разрешённое действие — с учётом прав администратора и необратимости удаления.

Что MAX действительно позволяет автоматизировать

В актуальном API есть отдельные методы получения, публикации, редактирования и удаления комментариев, а также события comment_created, comment_edited и comment_removed. Для автоматизации бот должен быть администратором канала с подходящими правами.

Получать новые комментарии

Событие приходит на HTTPS Webhook и содержит данные комментария, которые можно проверить по правилам.

Удалять нарушения

При наличии права delete бот может удалить комментарий. Восстановить удалённый комментарий через API нельзя.

Отвечать и уведомлять

При наличии нужных прав можно публиковать комментарий от бота или канала и объяснять причину действия.

Как проектируем правила модерации

Автоматические проверки

  • Стоп-слова и запрещённые выражения
  • Ссылки и повторяющиеся сообщения
  • Простые шаблоны спама
  • Отдельные правила для разных каналов
  • Журнал с причиной срабатывания
  • Тестовый режим до автоматического удаления

Где оставляем человека

  • Неоднозначные комментарии
  • Репутационно чувствительные ситуации
  • Сложный контекст и ирония
  • Изменение правил модерации
  • Разбор ложных срабатываний
  • Решения, которые нельзя безопасно откатить

MAX рекомендует заранее знакомить подписчиков с правилами канала. Мы также не включаем необратимое удаление до проверки правил на реальных примерах.

Практика PRAMIO

Модерация каналов — одна из задач собственного продукта АдминКИТ. Поэтому при проектировании учитываем не только API-вызов удаления, но и права бота, привязку каналов, повторные события, журнал решений и поведение при потере прав.
